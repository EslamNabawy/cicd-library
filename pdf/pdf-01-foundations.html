Continuous Integration

Concept · Reason · Cost of Skipping

3 / What Is Continuous Integration

Developers merge small changes into shared main frequently; every merge triggers an automated build + test + scan. CI answers one question: does this change work?

WHEN — on every push and every pull request. HOW — a pipeline job checks out the exact commit, builds it in a clean environment, and reports green or red back to the branch in minutes.

WHY THIS EXISTS

Without automated integration, a broken change travels for days before anyone discovers it. CI moves that discovery to within minutes of the commit — when the author still remembers what they did.

4 / What happens without CI/CD

  • Long-lived branches → merge hell. Weeks of divergent work collide; untangling takes days.
  • "Works on my machine" releases. Testing one thing, shipping another — every deploy a gamble.
  • Manual testing → bugs reach users. Humans skip steps under pressure.
  • Manual deploys → release fear. Rare, big, traumatic events nobody runs on Friday.
  • No feedback loop. The same bug class ships again and again.

Integration pain is paid minutes per commit with CI/CD, or weeks per release without it.

TriggerCommit / mergeValidated artifactValidated artifact

DO YOU DEPLOY TO PRODUCTION AUTOMATICALLY?
YES → CONTINUOUS DEPLOYMENTEvery passing change ships. Requires progressive delivery + instant rollback.
NO → CONTINUOUS DELIVERYEvery passing change is releasable. A human or policy decides when.

GOTCHA

A green build does not mean the application works in production. It means only the checks inside that pipeline passed.

13 / The Approval Gate

AUTOMATED: build ✓ · test ✓ · scan ✓ · artifact ✓  →  ◌ APPROVAL — a human decision is required  →  PRODUCTION

CONTEXT — PRODUCER & CONSUMER

The build pipeline produces the artifact; the deployment pipeline consumes it; the registry stores it. Lifecycle: build → store → promote → deploy. Anything that breaks this chain — a rebuild, a mutable tag, a skipped gate — voids every check upstream.

↓
TEST ✓300/300 pass
↓
SECURITY ✕critical CVE in base image

RECOVERY LOOP

FAILURE → LOGS → ROOT CAUSE → FIX → NEW COMMIT → PIPELINE. Every incident must land a new check, or it will recur.

GOTCHA

Never bypass a red gate with an admin override "just this once". The override becomes the process.

15 / Interview Check

Q: Delivery vs Deployment?
A: Delivery keeps software production-ready behind an approval; Deployment releases validated changes automatically.
Q: Why must staging and production share one artifact digest?
A: Otherwise you tested one binary and shipped another — verification is void.
