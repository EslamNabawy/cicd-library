01 / Why Jenkins

  • WHAT — open-source automation server: pipelines as code, 1,800+ plugins, controller + agents. Self-hosted, free, runs anywhere.
  • WHY — your data/secrets on your infra; reaches air-gapped networks and special hardware; no per-minute billing.

Topology

Roles · State · Channel
08
TOPOLOGY

Picking up from the Domain map — we now examine the controller–agent topology that every pipeline, agent, and credential later plugs into.

01 / The Three Parts

  • Controller — holds config (JENKINS_HOME), queue, history, UI/API, credentials. Runs no builds in production.
  • Agent — a machine offering executors: numbered slots, one build each.
  • Remoting — the channel shipping work out. Inbound = agent dials out (survives NAT); SSH = controller dials in (flat networks).

02 / What Lives in JENKINS_HOME

PathHolds
jobs/Job configs + build history
workspace/Checked-out code (rebuildable, deletable)
credentials.xml + secrets/Encrypted secrets — back up securely
config.xmlGlobal configuration

Failures & Handoff

Modes · Check · Next

05 / Failure Modes

  • Disk fills with old builds → UI freezes; fix with build discarders + log rotation.
  • Everything pinned to built-in node → single contention point; fix with labeled agents.
  • Clock skew → signatures/webhooks fail; run NTP everywhere.
Q: Controller vs agent responsibilities?
A: Controller schedules, serves, stores. Agents execute — nothing else.

Seven Steps

Run · Use · Verify

04 / Run & Use, End to End

1 · Run — container + volume + socket (above).
2 · Unlock — password, suggested plugins, admin user.
3 · Lock controller — built-in executors = 0.
4 · Agent — new node linux-1, labels linux docker, idle in Executor Status.
5 · Multibranch job — repo URL + credentials; Jenkinsfile discovered per branch.
6 · Webhook — /github-webhook/; push → build in seconds.
7 · Verify loop — green → staging → approve → production. Break it on purpose once.

02 / Declarative vs Scripted

DECLARATIVE (default, 95%) — opinionated skeleton, syntax-checked pre-run. SCRIPTED — raw Groovy (node { stage(…) }) for dynamic stages. Language: Apache Groovy; DSL steps documented in the built-in snippet generator.

pipeline {   agent { label 'linux' }   stages {     stage('Build') { steps { sh 'npm ci && npm run build' } }     stage('Test') { steps { sh 'npm test' }       post { always { junit 'reports/**/*.xml' } } }     stage('Image') { steps { sh 'docker build -t registry/app:$GIT_COMMIT .' } }   }   post { failure { mail to: 'team@acme.io' } } }

04 / Multibranch = PR Gates

A Multibranch job auto-discovers branches/PRs containing a Jenkinsfile and builds each independently — the Jenkins-native PR gate. Prefer it over hand-wired jobs per branch.

Wiring

Connection · Trust · Next

03 / Connection & Trust

  • Inbound — agent dials out via WebSocket; survives NAT, needs port 50000.
  • SSH — controller dials in; simple on flat networks, needs port 22 + credential.
  • Ephemeral wins — pristine container per run kills "works on my machine" and tool drift.

TRUST BOUNDARY

Never run untrusted fork PRs on permanent agents holding deploy credentials. Forks get isolated, credential-free agents — a malicious workflow otherwise owns your box.

  • Label typo → queue forever; check Executor Status.
  • Too many executors per CPU → starvation.
