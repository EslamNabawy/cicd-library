DECLARED ZONES

Picking up from ArgoCD & GitOps — IaC declares everything underneath the app: VPCs, clusters, databases, DNS, IAM. Same modules, different inputs per environment.

01 / Structure That Scales

envs/ ├── modules/ # vpc, cluster, db — written once ├── dev/ # small, short retention ├── staging/ # prod-shaped, sanitized data └── prod/ # real sizes, approvals
STATE PER ENV — one blast radius per state file, remote backend with locking. MODULES PINNED — floating sources are :latest with extra steps. ENV DIFF = INPUT DIFF — any other behavioral difference is a bug.

Pipeline

Plan · Drift

02 / IaC in the Pipeline

  • plan on every PR — the plan is the review.
  • apply gated like any prod deploy (auto dev, approved prod).
  • Drift detection nightly — the IaC equivalent of self-heal.
  • Preview envs: PR → Terraform workspace → ephemeral env → destroy on merge.

03 / Failure Modes

SHARED STATE lets dev apply delete prod — separate states, separate credentials. UNREVIEWED APPLY = ClickOps with extra steps. SECRETS IN STATE — state is plaintext; encrypt backends, use external stores.
Q: Staging behaves differently from prod — where do you look first?
A: The env inputs diff. If inputs match, it's drift or an undeclared change — both are bugs.
