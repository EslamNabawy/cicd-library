Picking up from GitHub Actions — GitLab goes further: repo, pipeline, registry, and environments are one product, so the pipeline natively knows merge requests and review apps.

01 / Pipeline Anatomy

stages: [build, test, deploy] build: stage: build script: [npm ci, npm run build] test: stage: test needs: [build] # DAG edge, no stage wait
RULES — stages order, same-stage jobs parallel · needs: DAGs across stages · rules: when jobs run (MR-only, main-only, paths) · artifacts: pass files on · cache: lockfile-keyed speed.

03 / Environments & Trains

  • Environments track what's deployed where; prod gates add approvals.
  • Review apps (with on_stop: teardown) = built-in preview envs per MR.
  • Merge trains serialize merges onto green main — the same race merge queues solve.
  • Failures: peak queues → tagged runners; silent skips → dry-run every rules: change; artifact bloat → expire_in:.
